# Printed performance treatment

The native video remains the sole media/audio source and retains its existing controls. `performance-print.js` copies the ambient landing preview image onto a canvas every **150 ms** (about **6.67 displayed frames/second**), using the same `PRINT_CADENCE_MS` constant as the letter/astronaut jitter. The clocks share a cadence, not a synchronized phase. No playback-rate, pitch, audio, seek or volume changes are made by the renderer. Explicit Play fades the held image out over 650ms, revealing unfiltered, full-frame-rate native video and stopping the canvas timer. Pause, seek and replay remain in regular-video mode; reduced-motion disables the fade.

The canvas uses the same `object-fit: cover` crop and existing section/seam clipping. Its source-aspect backing surface is capped at 960×540 on desktop and 640px wide on mobile, with no upscaling of small sources. A CSS-referenced SVG filter adds a 0.25px preblur, luminance mapping and gentle shadow lift, then eight discrete tones for more detail: `#121420`, `#292839`, `#514160`, `#546976`, `#8b8255`, `#c58930`, `#d4b579`, `#ead3a7`. Amber, warm gold and olive midtones keep it warm; purple and blue accents remain in the shadows. The original video is transparent only after a successful frame copy. It remains the accessible media source; the duplicate canvas is aria-hidden.

A single timer runs only while the source is in ambient mode, playing, ready, onscreen and the page is visible. Pausing or finishing refreshes the held frame once. Seeking holds the old frame until seek completion, then refreshes even while paused. Buffering holds the current image. Pagehide stops work and disconnects observation; pageshow restores it for the back/forward cache. Existing reduced-motion behavior in `living-video.js` prevents ambient playback and pauses when the preference changes; explicit Play remains available.

There are no pixel readbacks, WebGL texture uploads, CPU pixel loops or dependencies. Drawing cross-origin media for display does not need the readback permissions required by canvas export/getImageData. The actual public HLS master returned `Access-Control-Allow-Origin: *`; live browser QA used the existing HLS.js/MSE path successfully. See [MDN canvas image sources](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Using_images), [canvas cross-origin restrictions](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/CORS_enabled_image), and [discrete component mapping](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/tableValues).

If 2D context creation, frame copying or the context itself fails, the canvas is hidden and the original video remains usable at native frame rate, with the SVG palette only in ambient mode. This fallback preserves playback rather than promising a cadence the browser cannot render. Native decoding continues at source rate even in held-frame mode; the cap reduces canvas work, not codec work. Safari native-HLS and physical mobile hardware were not available for this pass; native media logic and failure cases have automated coverage.

The accompanying annotated refinements move transport controls to a narrower centered row (maximum 340px) beneath the upper ribbon without a visible time readout, reduce the wordmark containers to 86% desktop / 90% mobile while retaining their two-strip composition, and reuse `PaperCutout` for torn edges on the round Play button. Browser drafts are not adopted or rewritten.

Validation: 34 passing tests, including the seven renderer cadence/lifecycle/size/fallback tests plus existing playback/reduced-motion/gallery/studio tests. Real in-app browser QA verified live HLS display, normal-rate sound playback, pause/seek/resume/replay, volume/mute controls, desktop/mobile crop and positioning, bounded backing surfaces, and no console errors. The initial annotation overlay temporarily intercepted UI actions; normal UI verification succeeded after comments were submitted. No shared-server changes were made.
